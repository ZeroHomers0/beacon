# App-owned baseline profile for cold start.
#
# Class rules only (`L...;`), never method signatures: they name the startup path
# without pinning individual signatures, so an internal refactor moves code without
# invalidating the file, and a rename simply drops the stale rule. Anything heavy
# that startup does not touch is deliberately absent — a bloated profile dilutes
# the compile budget across code the user actually waits on.
#
# This adds to, and does not replace, the profiles AndroidX libraries already ship;
# the build merges both (see the merged_art_profile output of assembleRelease).
#
# Covered path: Application -> MainActivity -> first composition -> the runtime
# repository state the first frame reads.
